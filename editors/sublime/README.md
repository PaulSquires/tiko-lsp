# LSP-tiko for Sublime Text

Language support for **tiko** -- the FreeBASIC-compatible language of tiko-lang
-- served by [tiko-lsp](../../README.md), through Sublime's
[LSP](https://packagecontrol.io/packages/LSP) package. The Sublime twin of the
[Zed](../zed) and [VS Code](../vscode) extensions: a syntax called Tiko, the
path to a binary, and the toolchain settings the server needs. Everything else
-- diagnostics, completion, hover, go to definition, references, rename,
signature help, semantic tokens, inlay hints, formatting and quick fixes --
comes from the server.

Files: `.tiko`, `.tko`, `.ti`, and the legacy `.bas`, `.bi`, `.inc`.

## Install

1. Install the **LSP** package (Package Control: *Install Package* -> `LSP`).
2. Copy or link this directory into Sublime's `Packages` folder as `LSP-tiko`
   (*Preferences > Browse Packages...*). On Windows:

   ```bash
   mklink /J "%APPDATA%\Sublime Text\Packages\LSP-tiko" "C:\dev\tiko-lsp\editors\sublime"
   ```

   A junction keeps it current with this repository.

## Where it looks for the server

In order:

1. `server_path` in the settings;
2. the server in the toolchain folder named by `initializationOptions.toolchainPath`
   -- tiko comes with it: `tiko-lang\tiko-lsp.exe` on Windows,
   `tiko-lang/bin/tiko-lsp` on Linux and macOS;
3. `tiko-lsp` on your `PATH` -- which it is, beside `tiko`, if you put the toolchain
   on your `PATH`;
4. a `tiko-lang` folder where tiko-lang.net's instructions leave one: your home
   folder, Downloads (and one level below it), `C:\tiko-lang`, `/opt/tiko-lang`,
   `~/.local/tiko-lang`;
5. `bin/tiko-lsp.exe` inside a workspace folder -- so opening the tiko-lsp
   repository itself works after a build.

Leave an initialization option out to let the server decide: an empty
`"toolchainPath": ""` or `"compilerPath": ""` is an instruction that turns its own
search off.

If none of those finds it, LSP reports why the server could not start.

## Settings

*Preferences > Package Settings > LSP > Servers > LSP-tiko*:

```jsonc
{
    "server_path": "C:/dev/tiko-lsp/bin/tiko-lsp.exe",
    "server_arguments": ["--stdio"],
    "initializationOptions": {
        // The toolchain's inc: Win32, AfxNova and runtime names complete, hover
        // and show signatures. Its sibling pkg -- what #import "std/strings"
        // names -- is found on its own.
        "includePaths": ["C:/dev/tiko-editor-tiko/toolchains/tiko-windows/inc"],
        "packagePaths": []
    }
}
```

`initializationOptions` are read once, when the server starts: run
**LSP: Restart Servers** after changing them. Add `"--log-level", "debug",
"--log-file", "C:/temp/tiko-lsp.log"` to `server_arguments` to see what the
server is doing; it never writes to stdout.

## Colour and indentation

Sublime does not load tree-sitter grammars. `Tiko.sublime-syntax` and
`Indentation Rules.tmPreferences` are GENERATED by `python gen_sublime.py`:
the word lists from the Zed highlights query, the indent patterns from the VS
Code language configuration -- so all three editors agree. Re-run it when
either changes. Once the server is running, its semantic tokens refine the
colours (LSP's `semantic_highlighting` setting).
