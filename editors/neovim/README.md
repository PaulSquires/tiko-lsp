# tiko.nvim

Language support for **tiko** -- the FreeBASIC-compatible language of tiko-lang
-- in Neovim (0.10+), served by [tiko-lsp](../../README.md) through Neovim's
built-in LSP client. The Neovim twin of the [Zed](../zed), [VS Code](../vscode)
and [Sublime Text](../sublime) packages: a filetype called `tiko`, the path to
a binary, and the toolchain settings the server needs. Everything else --
diagnostics, completion, hover, go to definition, references, rename,
signature help, semantic tokens, inlay hints, formatting and quick fixes --
comes from the server.

Files: `.tiko`, `.tko`, `.ti`, and the legacy `.bas`, `.bi`, `.inc`.

## Install

With [lazy.nvim](https://github.com/folke/lazy.nvim):

```lua
{
  dir = 'C:/dev/tiko-lsp/editors/neovim',
  ft = 'tiko',
  opts = {
    include_paths = { 'C:/dev/tiko-editor-tiko/toolchains/tiko-windows/inc' },
  },
}
```

`ft = 'tiko'` alone would never load it -- the plugin is what DEFINES the
filetype -- so either drop `ft` or keep `lazy = false`. Without a plugin
manager, put the directory on the runtimepath and call setup in `init.lua`:

```lua
vim.opt.rtp:append('C:/dev/tiko-lsp/editors/neovim')
require('tiko').setup({
  include_paths = { 'C:/dev/tiko-editor-tiko/toolchains/tiko-windows/inc' },
})
```

## Where it looks for the server

In order:

1. `server_path` in `setup()`;
2. `tiko-lsp` on your `PATH`;
3. `bin/tiko-lsp.exe` under the project root -- so opening the tiko-lsp
   repository itself works after a build.

If none of those finds it, it says so once.

## Options

```lua
require('tiko').setup({
  server_path = nil,                      -- the executable; nil: PATH, then <root>/bin
  server_arguments = { '--stdio' },       -- add '--log-level', 'debug', '--log-file', 'C:/temp/tiko-lsp.log'
  include_paths = {},                     -- the toolchain's inc: Win32, AfxNova, runtime names
  package_paths = {},                     -- the toolchain's pkg; found beside inc on its own
  root_markers = { 'tiko.toml', '.git' }, -- the project root is the workspace the server scans
  legacy_extensions = true,               -- also claim .bas/.bi/.inc
})
```

`include_paths` and `package_paths` are sent as `initializationOptions`, which
the server reads once: `:TikoRestart` applies a change. `:TikoInfo` shows which
binary, root and paths are in use.

## Colour

`syntax/tiko.vim` is GENERATED by `python gen_vim_syntax.py` from the Zed
highlights query, so every editor colours the same words; re-run it when that
list changes. Neovim also applies the server's semantic tokens on top
(`:h lsp-semantic-highlight`). There is no tree-sitter parser registration
here: the grammar is at [../../grammar](../../grammar), but nvim-treesitter
would need it compiled for the platform.

## What is verified

Headless Neovim 0.11.4 (`nvim --headless --clean`, this plugin only), against
the real server and tracks/src: `tracks.bas` gets filetype `tiko`, the comment
and keyword syntax groups, a client rooted at the repository; hover on
`MessageBoxW` shows the winuser.bi declaration, signature help works inside
`MessageBoxW( 0, `, and `cfg.` completes `IsOk`, `Value`, `Failure`,
`ValueOr`. `:TikoInfo` reports, and `:TikoRestart` replaces the client.
